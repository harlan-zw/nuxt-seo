# Foundation source workspace

Foundation CI uses six source packages and a separate frozen lock.
It preserves the root supply-chain policy.
The full module CI workflow continues to check the complete collection.

The source workspace includes:

- `nuxtseo-shared`
- `nuxtseo-layer-devtools`
- `nuxtseo-devtools-host`
- `site-config-stack`
- `nuxt-site-config-kit`
- `nuxt-site-config`

Site Config uses the exact commit in `foundation-config.ts` and both foundation workflows.
Relative workspace links connect these packages during the build.
Published archives contain ordinary package versions.

## Verify the foundations

Use Node 22.22.3 or another supported Node version.
Checkout the pinned Site Config commit in a separate source directory.
Run this command from the Nuxt SEO checkout:

```sh
node scripts/bootstrap-foundation.ts \
  --output /absolute/scratch/foundation \
  --site-source /absolute/source/nuxt-site-config \
  --mode pack
```

The command installs with `--frozen-lockfile --no-trust-lockfile`.
It builds the source dependencies in order.
It runs Shared, Host, and UI unit tests before packing all six packages.
Archives appear in the output directory's `artifacts` folder.

Use an empty output directory for the first run.
The script creates `.foundation-workspace` before copying source packages.
Retries accept that marker and preserve evidence outside the six package directories.
Existing directories without that marker are rejected before any write or removal.
Source directories and their children are rejected, including paths through symlinks.

The source workspace excludes the meta module and consumer playgrounds.
Those projects require the consumer majors to exist in the npm registry.
Foundation CI supplements their existing checks.

## Refresh the foundation lock

If source manifests or catalog entries change, regenerate the separate lock.
Use a fresh output directory and the pinned Site Config source:

```sh
node scripts/bootstrap-foundation.ts \
  --output /absolute/scratch/foundation-lock-refresh \
  --site-source /absolute/source/nuxt-site-config \
  --mode generate
cd /absolute/scratch/foundation-lock-refresh
pnpm install --lockfile-only --no-frozen-lockfile --no-trust-lockfile
```

Copy the generated `pnpm-lock.yaml` to `scripts/foundation-lock.yaml`.
Review dependency changes and rerun `--mode pack` with a fresh output directory.
Keep registry integrity values generated by pnpm.
Do not copy temporary tarball overrides into the source policy or lock.

If the Site Config pin changes, update the helper and both workflow references together.
Then refresh the foundation lock and verify the source workspace.

## Release selection

The Foundation Release workflow uploads all six verified archives by default.
Its optional publication step permits only Shared, UI, and Host.
Its publication order is Shared, then UI, then Host.
Site Config companions use their repository's release process.
The meta module keeps its existing version and release process.

Each published package requires an npm trusted-publisher configuration for `foundation-release.yml`.
pnpm 12.8.1 supports native GitHub OIDC publication and provenance.
The workflow grants `id-token: write` and supplies no npm token.
Configure a new package's initial publication through the maintainer's npm process.

The release script validates every selected archive before publishing any package.
Select `publish` only when the maintainer intends to release the selected versions.
