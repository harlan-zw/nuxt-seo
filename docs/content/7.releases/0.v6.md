## Introduction

Nuxt SEO v6 moves every bundled module to a new major version. Two modules join the bundle: [AI Ready](/docs/ai-ready/getting-started/introduction) and [Skew Protection](/docs/skew-protection/getting-started/introduction).

The release drops Nuxt 3. Every module now requires Nuxt 4.6 or Nuxt 5, and Node 22.22.3+, 24.15.0+, or 26+. That floor lets the modules use Nuxt's portable server APIs, so each module carries less code of its own.

v6 installs two more modules and still weighs less. Against 5.3.16, it ships 44% less JavaScript to the browser, and its server build is 52% smaller.

Most projects need three changes: upgrade Nuxt, install the DevTools host, and check OG Image signing. Breaking Changes below lists the rest.

## 🤖 AI Ready and Skew Protection, Bundled

`@nuxtjs/seo` now installs nine modules. AI Ready and Skew Protection install with the rest.

**AI Ready** makes your pages readable by AI agents. It generates `llms.txt` and `llms-full.txt`, and serves every page as Markdown at a `.md` URL. It publishes Agent Skills from `public/skills/<name>/SKILL.md`, and generates an API catalog when you configure an MCP server and a site URL.

**Skew Protection** keeps the assets of earlier builds available after a deploy. Open tabs and crawlers stop hitting `ChunkLoadError` and 404s on old chunks. Under Nuxt SEO it checks for new versions with Nuxt's hourly app manifest polling, so it opens no persistent connection. It also sets no version cookie.

Your options still go under the module keys. To turn either module off, set its key to `false`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@nuxtjs/seo'],
  aiReady: false,
  skewProtection: false,
})
```

::warning
By default, Skew Protection stores old assets in `node_modules/.cache/nuxt-seo/skew-protection`. If your CI discards that directory between deploys, cache it. Otherwise each deploy loses the assets of earlier builds.
::

## ⚡ Performance

We built the same app on 5.3.12 (before the August performance work), 5.3.16 (the last v5 release), and v6. Each app installs every module, Nuxt i18n with two locales, and Satori for OG images. "Over bare Nuxt" is the cost on top of the same app without Nuxt SEO.

| | 5.3.12 | 5.3.16 | v6 |
|---|---|---|---|
| Nuxt SEO JavaScript in the browser, gzip | 22.6 KB | 26.8 KB | **14.9 KB** |
| Server build output, gzip | 12.5 MB | 8.7 MB | **4.2 MB** |
| Install size, over bare Nuxt | 108 MB | 125 MB | **73 MB** |
| Server memory after boot, over bare Nuxt | 146 MB | 148 MB | **14 MB** |
| Memory allocated per page render, over bare Nuxt | 1,031 KB | 954 KB | **921 KB** |

- **Browser JavaScript, 44% less than 5.3.16.** Schema.org's default mode and Robots' bot detection no longer ship code to the browser. Skew Protection's polling default saves 4.2 KB of the 11.9 KB.
- **Server build, 52% smaller.** AI Ready's Markdown converter now installs only your platform's native binary, not one for every platform ([nuxt-ai-ready#171](https://github.com/harlan-zw/nuxt-ai-ready/pull/171)).
- **Install size, 42% smaller.** `drizzle-orm`, `zod`, `chrome-launcher`, `sharp`, and mdream's binaries for other platforms are now optional or gone. The test app also installs Satori, resvg, and `better-sqlite3`. Without them, Nuxt SEO adds 15 MB to a bare app. If you render OG images, add the renderer you choose.
- **Boot memory, 14 MB.** v5 AI Ready loaded its database code at startup, even with the database off. v6 loads it only when a feature needs it. A v5 app without AI Ready never paid this cost.

## 🩺 Setup Checks in Development

Missing configuration used to stay silent until a crawler found the result. In v6, the first successful home page response in `nuxt dev` starts a background check across every installed module.

- **Required checks** report once per server start. Each one names the fix, the reason, and a docs link. A missing `site.url` is one of them.
- **Tips** suggest optional features that fit your app, such as a Sitemap or OG Image setting you have not enabled. After tips show, they stay quiet for seven days in that project. Required checks ignore this pause.

The same checks appear in the Nuxt SEO DevTools panel, with a refresh action. CI and AI agent sessions skip the terminal output. To hide tips but keep required checks, set `tips` to `false`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nuxtseo: { tips: false },
})
```

## 🧩 DevTools on Demand

The DevTools hosting code used to install for every user, including people who never open a panel. In v6 it lives in an optional package, `nuxtseo-devtools-host`. The shared core now installs 7 runtime dependencies, down from 14.

If you use the SEO panels in Nuxt DevTools, add the host as a development dependency:

```bash
npx nypm add -D nuxtseo-devtools-host
```

If the host is missing, each panel shows an install button.

## 🛡️ Version Checks That Fail the Build

Before v6, `@nuxtjs/seo` could run with the wrong module versions and report nothing.

- On a Nuxt version without module dependency support, no module installed. `/robots.txt` and `/sitemap.xml` returned 404 and the build passed.
- Nuxt checked the module copy nested inside `@nuxtjs/seo`, and loaded the copy your app resolved. A pinned older module passed the check.

Now a pinned older module stops the build and names the problem:

```text
ERROR  [@nuxtjs/seo] Module `@nuxtjs/sitemap` version (`8.6.1`) does not satisfy `>=9.0.0` (requested by `@nuxtjs/seo`).
```

An unsupported Nuxt version also stops the build. The error names your version, the required range, and the fix:

```text
ERROR  [@nuxtjs/seo] Nuxt 4.5.2 is not supported. @nuxtjs/seo requires Nuxt `^4.6.1 || ^5.0.0`. To upgrade Nuxt, run `npx nuxt upgrade`.
```

`nuxtseo: false` also works now. Before v6 it type checked but installed every module anyway. It now installs none of the bundled modules. A module that you add to `modules` yourself still installs.

## 🖼️ OG Image v7

OG Image v7 changes how images render, cache, and sign. Read the [OG Image v7 migration guide](/docs/og-image/migration-guide/v7) before you upgrade a project with custom templates.

- **Native Satori layout.** Satori 0.47 supports block, inline, and grid layout, plus `translate`, `rotate`, and `scale`. Templates now behave more like regular CSS. Bare `<div>`{lang="html"} elements no longer get a forced `display: flex`.
- **Publish to storage.** Serve generated images from a public R2 or S3 mount. Repeat requests skip the render, and builds reuse published images until their cache expires.
- **Fonts from `@nuxt/fonts` v1.** Prerendered images keep their fonts, and Takumi loads OTF and WOFF files.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  ogImage: {
    publish: { storage: 'og-image-public', baseURL: 'https://images.example.com' },
  },
  nitro: {
    storage: {
      'og-image-public': { driver: 'cloudflare-r2-binding', binding: 'OG_IMAGES' },
    },
  },
})
```

## 🤖 Robots: Block Training Crawlers Only

Robots v7 adds `blockAiBots: 'training'`. It blocks crawlers that collect model training data, such as GPTBot, ClaudeBot, Google-Extended, and CCBot. AI search and answer agents can still read your site.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  robots: { blockAiBots: 'training' },
})
```

Google-Extended also controls [Gemini](https://gemini.google.com) grounding. Blocking it removes your pages from that use too.

`definePageMeta({ robots })`{lang="ts"} now matches routes through your app's own router. It respects `sensitive`, `strict`, aliases, and i18n routes, so a private page no longer stays indexable because of a path mismatch.

## 🧭 More Module Improvements

- **Sitemap v9.** `definePageMeta({ sitemap: false })`{lang="ts"} also excludes prerendered dynamic pages, aliases, and case or trailing slash variants. Builds without streaming or compression drop that code.
- **Schema.org v7.** In the default non-reactive mode, `useSchemaOrg()`{lang="ts"} and the `define*()` helpers leave the client bundle again. The SSR JSON-LD output is unchanged.
- **SEO Utils v9.** Development and build warn when an indexable page renders only on the client, with a config example to copy. Derived meta tags take about half the CPU time per call.
- **Link Checker v6.** A build that scans no pages now says so in its log. Reports show the real HTTP status text, and a `HEAD` request that gets 405 or 501 retries with `GET`.
- **Site Config v5.** `getSiteConfig(event)`{lang="ts"} now works in your `server/middleware`. A prerender without `site.url` now warns, where it used to render relative URLs silently.
- **AI Ready v3.** Markdown negotiation reads the `Accept` header only, so caches need one `Vary` header. The AI Catalog at `/.well-known/ai-catalog.json` is also served at `/.well-known/ard.json`.
- **Skew Protection v2.** Open tabs share one connection through Web Locks. Core protection works without Robots or Site Config.

## 🧠 Agent Skill in the Package

`@nuxtjs/seo` now ships an Agent Skill at `skills/nuxtjs-seo/SKILL.md`. It tells a coding agent which module owns each config key, how to disable a module, and which install errors to expect. Get it on [skilld.dev](https://skilld.dev/gh/harlan-zw/nuxt-seo/nuxtjs-seo). Every bundled module now ships its own Agent Skill too.

## ⚠️ Breaking Changes

### Nuxt 4.6.1 and Node 22.22.3 Minimum

Nuxt SEO v6 requires Nuxt `^4.6.1 || ^5.0.0`. Nuxt SEO v6 no longer supports Nuxt 3.

Node must match `^22.22.3 || ^24.15.0 || >=26.0.0`.

### AI Ready and Skew Protection Install by Default

Remove `nuxt-ai-ready` and `nuxt-skew-protection` from your `modules` array and your dependencies. `@nuxtjs/seo` installs them. Keep your options under `aiReady` and `skewProtection`, or set either key to `false`.

If you already configured Skew Protection, check these v2 changes:

- An unset `updateStrategy` now means hourly polling on every platform. For instant updates, set `updateStrategy: 'sse'` or `'ws'`.
- `experimental.appManifest: false` now fails setup.
- The default storage driver is `fs-lite`. An explicit `driver: 'fs'` still works.
- With `multiTab: true`, tabs share one push connection. To keep one connection per tab, set `multiTab: false` or `connectionTracking: true`.

If you already configured AI Ready, AI bots no longer get Markdown by User-Agent alone. Set `botNegotiation: true` to restore that. AI Ready drops the `better-sqlite3` fallback and uses `node:sqlite`.

### DevTools Panels Need `nuxtseo-devtools-host`

Install `nuxtseo-devtools-host` as a development dependency to keep the SEO panels. The DevTools on Demand section above shows the command.

### OG Image Signing Uses `NUXT_APP_SECRET`

If URL signing is on, set `NUXT_APP_SECRET` to a value of at least 32 characters. Without it, production image and page requests return a 500 error. If `security.secret` holds a string, remove it from your config. Generate a secret with `npx nuxt-og-image generate-secret`.

`NUXT_OG_IMAGE_SECRET` still works with a deprecation warning. Signed URLs from OG Image v6 become invalid, so purge cached HTML that contains them.

The [OG Image v7 migration guide](/docs/og-image/migration-guide/v7) also covers these changes:

- OG Image needs Satori 0.47. Add `flex flex-col` to elements that depended on the old forced flex layout.
- OG Image needs Takumi v2 (`^2.15.0`). Replace `takumi.fetchedResources` and `takumi.persistentImages` with `takumi.images`.
- Custom fonts need `@nuxt/fonts` v1. Families used only in OG images need `global: true`.

### Zod 4 for Nuxt Content Schemas

`defineRobotsSchema()`{lang="ts"}, `defineSitemapSchema()`{lang="ts"}, and `defineOgImageSchema()`{lang="ts"} require [Zod](https://zod.dev) 4. Upgrade the `zod` package in your app.

### Server Hooks Receive a `RequestEvent`

The `robots:*` and `sitemap:*` hook contexts now carry a `RequestEvent` from `nuxt/server`, in place of an h3 `H3Event`. Read request headers with the web API:

```ts [server/plugins/sitemap.ts]
export default defineNitroPlugin((nitroApp) => {
  nitroApp.hooks.hook('sitemap:sources', (ctx) => {
    // v5: ctx.event.node.req.headers.authorization
    const auth = ctx.event.req.headers.get('authorization')
  })
})
```

OG Image's `getOgImageUrl()`{lang="ts"} also takes a `RequestEvent`. Import `defineEventHandler` from `nuxt/server` in handlers that call it.

### Site Config Priority and Values

- `updateSiteConfig()`{lang="ts"} without `_priority` now ranks below your `site` key and `NUXT_SITE_*` variables. Pass `_priority: SiteConfigPriority.runtime` to keep the old order.
- `indexable` is now always a boolean. It defaults to `env === 'production'`.
- Module authors: Site Config v5 drops `installNuxtSiteConfig()`{lang="ts"}. Declare `nuxt-site-config` in `moduleDependencies`.

### Smaller Module Changes

- **Robots:** Robots v7 drops the `#internal/nuxt-robots` and `#internal/nuxt-simple-robots` aliases. Import from `#robots/server` or `#robots/app`. `robots.txt` files in `assets/` or `pages/` resolve from `srcDir` (`app/` in Nuxt 4).
- **Robots:** `noai` and `noimageai` route rules no longer mark a route as not indexable. A `robots:config` change made during a request now affects only that request.
- **Robots:** route rules now take precedence over `definePageMeta({ robots })`{lang="ts"}. If both set a rule for a page, the route rule wins.
- **Sitemap:** Sitemap v9 drops `nuxt-simple-robots` support. Use `@nuxtjs/robots` v7.
- **Link Checker:** Link Checker v6 drops Nuxt Content v2 support. Reports show the real status text, and an unreachable link reports status `0`.
- **SEO Utils:** `sharp` is an optional peer dependency. Add it to use `nuxt-seo-utils icons`. Runtime minification no longer rewrites inline JavaScript.
- **Schema.org and SEO Utils:** the bare `#schema-org` and `#seo-utils` aliases are replaced by `#schema-org/app`, `#schema-org/server`, and `#seo-utils/app`.
- **Nuxt Content:** Nuxt SEO v6 no longer supports Nuxt Content v2. Use Content v3.

## ✅ Upgrading

The [v5 to v6 migration guide](/docs/nuxt-seo/migration-guide/v5-to-v6) covers each change step by step. Upgrade Nuxt first, then Nuxt SEO:

```bash
npx nuxt upgrade
npx nypm add @nuxtjs/seo@^6
npx nypm add -D nuxtseo-devtools-host
```

If you pinned a bundled module in your `package.json`, update it to the version in the [table below](#module-versions) or remove it. An older pinned module now fails the build.
